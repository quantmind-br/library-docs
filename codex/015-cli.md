# OpenAI Codex CLI

> **BLUF:** Codex CLI is an open-source, terminal-native agent that reads local code, executes commands, and edits files. It runs in "Full Automation" (unsupervised, sandboxed) or "Human-in-the-Loop" (approval required) modes. Supports OpenAI, Azure OpenAI, and third-party models via OpenAI-compatible APIs.

## Quickstart

1. **Install:** `npm install -g @openai/codex`
2. **Login:** `codex login`
3. **Run:** `codex "your request"`

> ⚠️ Requires Node.js 22+. macOS 13+, Ubuntu/Debian, or WSL.

## Models

| Model | Best For | Notes |
|-------|----------|-------|
| o4-mini | Fast, cost-efficient tasks | Default |
| o3 | Complex, multi-step reasoning | Higher cost |
| GPT-4.1 | Large context (1M tokens) | Best for big codebases |

Set via `--model <model>` or `OPENAI_MODEL` env var.

## Core Commands

| Command | Description |
|---------|-------------|
| `codex --help` | Show all flags |
| `codex -q <prompt>` | Non-interactive mode |
| `codex -a <prompt>` | Full auto mode (no approval) |
| `codex -i <prompt>` | Interactive mode (default) |
| `codex login` | Authenticate |
| `codex logout` | Remove API key |
| `codex models` | List available models |

## Approvals & Modes

### Full Auto (`-a`)
- No user intervention required
- Commands run in network-disabled sandbox
- Files written to `.codex/` review directory first
- Applied after task completion or on explicit user request

> ✅ All file changes reviewed via `git diff` before staging. User must explicitly stage (`git add`) and commit changes. Supports custom review commands via `--approval-policy=full-auto`.

### Human-in-the-Loop (`-i`)
- Agent asks before every file write and shell command
- Safer for production environments

### Config Levels
1. CLI flag (`--approval-policy`)
2. Environment variable (`OPENAI_APPROVAL_MODE`)
3. Config file (`~/.codex/config.yaml`)
4. Project config (`.codex/config.yaml`)

Lower levels override higher levels.

## Safety & Security

### Sandbox Architecture
- **macOS:** `seatbelt` profile (network disabled, filesystem restricted)
- **Linux:** Landlock + Seccomp (no network access)
- Windows support via WSL

### Key Features
- Full `git` integration (diff review required before commit)
- `CODEX_QUIET_MODE=1` strips PII (stdin, stdout, env vars, secrets)
- 30s timeout on file reads (configurable)
- `.gitignore` respected automatically

### Sensitive Directories
Explicit approval required for:
- `~/.*`
- `/etc/`
- System paths (`/bin`, `/usr`, etc.)

## Configuration

### Files
- `~/.codex/config.yaml` — global
- `~/.codex/instructions.md` — global instructions
- `.codex/config.yaml` — project-level
- `.codex/instructions.md` — project instructions

### Key Settings
```yaml
model: o4-mini
approvalMode: suggest-full-auto  # or full-auto, human-in-the-loop
notify: true                     # desktop notifications
safeCommands: ["npm test", "npm run build"]  # no-approval list
```

### Environment Variables
| Variable | Description |
|----------|-------------|
| `OPENAI_API_KEY` | API key |
| `OPENAI_MODEL` | Default model |
| `OPENAI_ORG_ID` | Organization ID |
| `OPENAI_PROJECT_ID` | Project ID |
| `OPENAI_APPROVAL_MODE` | Default approval mode |
| `CODEX_DISABLE_UPDATE_CHECK` | Skip update checks |

### API Endpoints
| Variable | Description |
|----------|-------------|
| `OPENAI_BASE_URL` | Custom base URL |
| `AZURE_OPENAI_BASE_URL` | Azure endpoint |
| `AZURE_OPENAI_API_KEY` | Azure key |
| `AZURE_OPENAI_API_VERSION` | API version (default: `2025-03-01-preview`) |
| `AZURE_OPENAI_MODEL_DEPLOYMENTS` | Deployment mapping |

### MCP Servers
Configure in `~/.codex/config.yaml` or `~/.codex/mcp.json`:
```yaml
mcpServers:
  my-server:
    command: uvx
    args: [-m, my_mcp_server]
```

Supports `stdio` and `SSE` (Server-Sent Events). Run `codex mcp add <name> <command> [args...]` to add via CLI.

## Custom Instructions

Place in `.codex/instructions.md` or `~/.codex/instructions.md`:
- Coding style preferences
- Testing requirements
- Architecture decisions
- Team conventions

Example: "Always use TypeScript strict mode. Run tests before completing any task."

## Non-Interactive Mode (`-q`)

```bash
codex -q "explain this codebase" > explanation.md
codex -q --image screenshot.png "fix the bug shown"
```

- Single-shot execution
- No REPL session
- Supports image attachments with `--image`

## Tips & Best Practices

| Tip | Why |
|-----|-----|
| Pin versions in `package.json` | Avoids supply-chain drift |
| Run tests after Codex edits | Catch hallucinated APIs |
| Use `git` for all changes | Enables diff review |
| Keep custom instructions under 200 lines | Improves performance |
| Batch related tasks | Reduces context overhead |

## Troubleshooting

| Issue | Fix |
|-------|-----|
| `zsh: command not found: codex` | Ensure Node.js 22+ is active; check `npm bin -g` |
| `401 Invalid Authentication` | Run `codex login` or set `OPENAI_API_KEY` |
| Sandbox errors | Update to latest CLI version |
| Model not found | Run `codex models` to list available models |
| Rate limits | Switch to `o4-mini` or add retry logic |
