# Model Context Protocol

MCP connects models to tools and context. Give Codex access to third-party documentation or let it interact with developer tools like your browser or Figma.

Supported in both CLI and IDE extension.

## Supported MCP features

- **STDIO servers** — local process started by a command
  - Environment variables
- **Streamable HTTP servers** — accessed at an address
  - Bearer token authentication
  - OAuth authentication (`codex mcp login <server-name>`)

## Connect Codex to an MCP server

MCP configuration stored in `config.toml` alongside other Codex settings. Default: `~/.codex/config.toml`; can scope to project with `.codex/config.toml` (trusted projects only).

CLI and IDE extension share configuration. Switch between clients without redoing setup.

Configuration options:
1. **CLI**: `codex mcp` to add and manage servers
2. **Edit `config.toml`** directly

### CLI

#### Add an MCP server

```bash
codex mcp add <server-name> --env VAR1=VALUE1 --env VAR2=VALUE2 -- <stdio server-command>
```

Example (Context7 — free MCP server for developer documentation):
```bash
codex mcp add context7 -- npx -y @upstash/context7-mcp
```

#### Other CLI commands

Run `codex mcp --help` for all available commands.

#### TUI

In `codex` TUI, use `/mcp` to see active MCP servers.

### config.toml

For fine-grained control, edit `~/.codex/config.toml` (or project-scoped `.codex/config.toml`). In IDE extension: **MCP settings** > **Open config.toml** from gear menu.

Configure each server with `[mcp_servers.<server-name>]` table.

#### STDIO servers

- `command` (required): command that starts the server
- `args` (optional): arguments to pass
- `env` (optional): environment variables to set
- `env_vars` (optional): environment variables to allow and forward
- `cwd` (optional): working directory
- `experimental_environment` (optional): `remote` to start through remote executor

`env_vars` can contain plain names or objects with source:
```toml
env_vars = ["LOCAL_TOKEN", { name = "REMOTE_TOKEN", source = "remote" }]
```

String entries and `source = "local"` read from Codex's local environment. `source = "remote"` reads from remote executor environment (requires remote MCP stdio).

#### Streamable HTTP servers

- `url` (required): server address
- `bearer_token_env_var` (optional): env var name for bearer token in `Authorization`
- `http_headers` (optional): static header name → value map
- `env_http_headers` (optional): header name → env var name map

#### Other configuration options

- `startup_timeout_sec` (default `10`): server startup timeout
- `tool_timeout_sec` (default `60`): tool execution timeout
- `enabled` (default `true`): disable without deleting
- `required` (default `false`): fail startup if server can't initialize
- `enabled_tools` (optional): tool allow list
- `disabled_tools` (optional): tool deny list (applied after `enabled_tools`)

OAuth callback overrides:
- `mcp_oauth_callback_port`: fixed callback port (default: ephemeral)
- `mcp_oauth_callback_url`: specific callback URL (e.g., remote Devbox ingress)

If server advertises `scopes_supported`, Codex prefers those during OAuth login; otherwise falls back to `config.toml` scopes.

#### config.toml examples

```toml
[mcp_servers.context7]
command = "npx"
args = ["-y", "@upstash/context7-mcp"]
env_vars = ["LOCAL_TOKEN"]

[mcp_servers.context7.env]
MY_ENV_VAR = "MY_ENV_VALUE"
```

```toml
mcp_oauth_callback_port = 5555
mcp_oauth_callback_url = "https://devbox.example.internal/callback"
```

```toml
[mcp_servers.figma]
url = "https://mcp.figma.com/mcp"
bearer_token_env_var = "FIGMA_OAUTH_TOKEN"
http_headers = { "X-Figma-Region" = "us-east-1" }
```

```toml
[mcp_servers.chrome_devtools]
url = "http://localhost:3000/mcp"
enabled_tools = ["open", "screenshot"]
disabled_tools = ["screenshot"]  # applied after enabled_tools
startup_timeout_sec = 20
tool_timeout_sec = 45
enabled = true
```

| Server | Purpose |
|--------|---------|
| [OpenAI Docs MCP](https://developers.openai.com/learn/docs-mcp) | Search and read OpenAI developer docs |
