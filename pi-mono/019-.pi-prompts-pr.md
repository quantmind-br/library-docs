# Pull Request Review

Review PR(s): $@

## Process

1. Add `inprogress` label via GitHub CLI. If fails, report and continue.
2. Read PR in full (description, comments, commits, changed files).
3. Identify linked issues from PR body, comments, commit messages. Read each issue fully.
4. Analyze PR diff. Read all relevant code files from main branch and compare. Validate behavior against related code paths not in diff.
5. Check changelog entry in `packages/*/CHANGELOG.md`. If missing, state that entry is required before merge. Verify:
   - Correct section (`### Breaking Changes`, `### Added`, `### Fixed`, etc.)
   - External contributions include PR link and author
   - Breaking changes in `### Breaking Changes` section

6. Check if README, docs, or examples need modification.

## Review Format

Output per PR:
```
PR: <url>
Changelog:
- ...
Good:
- ...
Bad:
- ...
Ugly:
- ...
Questions or Assumptions:
- ...
Change summary:
- ...
Tests:
- ...
```

If no issues found, say so under Bad and Ugly.

> [!note]
> If `packages/coding-agent/README.md`, `packages/coding-agent/docs/*.md`, or `packages/coding-agent/examples/**/*.md` require changes, flag these in the review.
