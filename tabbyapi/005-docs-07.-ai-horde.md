# 07. AI Horde

Configure TabbyAPI as a backend for the [AI Horde](https://aihorde.net/) crowdsourced compute pool. TabbyAPI is the only Horde-compatible LLM server running on Windows with parallel batching.

## Prerequisites

Get an API key at [stablehorde.net/register](https://stablehorde.net/register).

The LLM branch uses KoboldAI's API (not OpenAI standard).

## Configure TabbyAPI

1. In `config.yml`, set `api_servers` to include `"Kobold"` to enable the KoboldAI API.
2. Enable `disable_auth` in `config.yml` (Horde doesn't support API key authentication).
3. Launch TabbyAPI — it's now Horde-ready.

## Set Up the Worker

The Horde needs a "worker" to interface between its servers and your TabbyAPI backend.

1. Clone the worker repository:
   ```bash
   git clone https://github.com/Haidra-Org/AI-Horde-Worker
   ```
2. Copy `bridgeData_template.yaml` to `bridgeData.yaml`.

### Recommended Configuration

| Parameter | Description |
|---|---|
| `api_key` | Your Horde API key |
| `max_threads` | Concurrent requests; pair higher values with larger batch/cache size in Tabby |
| `scribe_name` | Display name for your worker |
| `kai_url` | TabbyAPI backend URL, usually `http://localhost:5000` |
| `max_length` | Max tokens per request; 512 recommended |
| `max_context_length` | Max context length; set to model's `max_seq_len` |

## Launch

Run `.\horde-scribe-bridge.bat` (Windows) or `./horde-scribe-bridge.sh` (Linux/macOS).
