Version: 1.2

`dms doctor` diagnoses your DMS installation, verifies dependencies, and checks system configuration.

## Usage

```bash
dms doctor           # Standard output
dms doctor -v        # Verbose output with paths and details
dms doctor -j        # JSON output for scripting
```

## Status Indicators

| Icon | Status | Meaning |
|------|--------|---------|
| 🟢 OK | Check passed |
| 🟡 Warning | Non-critical issue, may affect some features |
| 🔴 Error | Critical issue that needs attention |
| ⚪ Info | Informational, no action needed |

---

## System Checks

### Operating System

All GNU/Linux distributions are supported (informational only).

### Architecture

Only `amd64`/`arm64` is officially supported; other architectures may work with manual compilation.

### Display Server

DMS supports Wayland only; verifies you are not using X11.

---

## Version Checks

### DMS CLI

DMS CLI is the backend/CLI. Its version must match the quickshell configuration version.

### Quickshell

Quickshell is DMS's framework. Older versions may result in a reduced feature set.

### DMS Shell

The shell configuration version, which should match the DMS CLI version.

---

## Installation Checks

### DMS Configuration

DMS installs its configuration, plugins, and themes in `$XDG_CONFIG_HOME/.config/DankMaterialShell/`.

### shell.qml

The installed location of the DMS shell configuration.

### Install Type

| Type | Description |
|------|-------------|
| `system` | Installed via system package manager (`apt`, `dnf`, `pacman`) |
| `user` | Manually compiled and installed |
| `nix` | Installed via Nix package manager |

---

## Compositor Checks

DMS supports all compositors implementing the [layer shell protocol](https://wayland.app/protocols/wlr-layer-shell-unstable-v1), with varying feature sets.

### Supported Compositors

| Compositor | Detection Command |
|------------|-------------------|
| niri | `niri --version` |
| Hyprland | `hyprctl version` |
| mangowc | `mangowc --version` |
| labwc | `labwc --version` |
| Sway | `sway --version` |
| River | `river -version` |
| Wayfire | `wayfire --version` |

### Active Compositor

Currently running compositor.

---

## Quickshell Features

These depend on how Quickshell was built. Using `quickshell-git` provides full feature support.

> [!note]
> All features require `quickshell-git` or `quickshell` from Dank Linux repositories (Fedora, Debian, Ubuntu, OpenSUSE).

| Feature | Purpose |
|---------|---------|
| Polkit | Escalation prompts requiring root authorization |
| IdleMonitor | Auto lock, power off monitors, suspend, hibernate |
| IdleInhibitor | Prevent system from idling or sleeping |
| ShortcutInhibitor | Manage keyboard shortcuts (niri-specific) |

---

## Optional Features

| Feature | Description |
|---------|-------------|
| accountsservice | Persist user profile changes (e.g., profile picture) |
| power-profiles-daemon | Manage power profiles (performance, balanced, power-saver) |
| I2C/DDC | External monitor brightness control; requires `i2c-tools` and `i2c` group membership |
| matugen | Generate themes via [[046-docs-1.2-dgop|dgop]] integration (Dank16 color enrichment) |
| dgop | System monitoring widgets and applets (CPU, RAM, Disk, Network, Processes) — see [[046-docs-1.2-dgop|dgop documentation]] |
| cava | Audio visualization in media players |
| khal | Calendar enrichment from local, CalDAV, or other khal-supported sources |
| Network | Integration with NetworkManager, iwd, systemd-networkd |
| danksearch | Indexed filesystem search in the launcher (initiated with `/`) — see [[076-docs-1.2-danksearch|danksearch documentation]] |
| loginctl | Session management (systemd/elogind); lock integration, lock before suspend |
| fprintd | Fingerprint authentication on the lock screen |

### Network Backends

| Backend | Support |
|---------|---------|
| NetworkManager | All features (Wifi, Ethernet, VPN) — recommended |
| iwd | Wifi only, no Ethernet or VPN |
| systemd-networkd | Ethernet only, no Wifi or VPN |
| iwd+systemd-networkd | Wifi + Ethernet, no VPN |

### Terminals (detected in priority order)

`ghostty`, `kitty`, `alacritty`, `foot`, `wezterm`

## Configuration Files

| File | Location | Purpose |
|------|---------|---------|
| `settings.json` | `~/.config/DankMaterialShell/` | Main settings |
| `clsettings.json` | `~/.config/DankMaterialShell/` | Clipboard settings |
| `plugin_settings.json` | `~/.config/DankMaterialShell/` | Plugin configuration |
| `session.json` | `~/.local/state/DankMaterialShell/` | Session state |
| `dms-colors.json` | `~/.cache/DankMaterialShell/` | Cached color scheme |

---

## Services

### dms.service

If in use, DMS lifecycle is managed by systemd. Optional — DMS can also be started manually or via other init systems.

### greetd

Required for the Dank Greeter. See [[096-docs-1.2-dankgreeter|dankgreeter documentation]].

---

## Environment Variables

### QT_QPA_PLATFORMTHEME

Sets the Qt platform theme (`gtk3`, `qt6ct`, or `kde`). Defines how Qt applications and some DMS elements (icon themes) are themed.

### QS_ICON_THEME

Sets the icon theme for DMS only. Does not affect other applications.

## JSON Output

`dms doctor -j` produces machine-readable output:

```json
{
  "summary": { "errors": 0, "warnings": 1, "ok": 15, "info": 5 },
  "results": [
    {
      "category": "System",
      "name": "Operating System",
      "status": "ok",
      "message": "Arch Linux",
      "details": "ID: arch, Version: rolling, Arch: amd64"
    }
  ]
}
```

## Welcome Wizard Integration

Doctor checks are available in the Welcome Wizard's System Check page:

```bash
dms ipc call welcome doctor
```

Or via Settings → About → Tools → System Check.
