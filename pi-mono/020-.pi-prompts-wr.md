# Task Wrap-up

Wrap it up: $ARGUMENTS

## Context Detection

- If conversation mentions GitHub issue or PR, use that context
- If work came from `/is` or `/pr`, context is already known
- If no GitHub issue/PR, treat as non-GitHub work

## Steps (in order)

1. **Add/update changelog entry** under `## [Unreleased]` in relevant package (follow repo changelog rules)
2. **Post GitHub comment** if tied to issue/PR and no final comment posted in session. Draft in your tone, preview, post exactly one comment.
3. **Commit only files changed in this session**
4. **Include `closes #<issue>`** in commit message if tied to exactly one GitHub issue. If tied to multiple, stop and ask which to use. If none, omit `closes`/`fixes`.
5. **Check current branch** — if not `main`, stop and ask. Do not push from another branch unless explicitly told.
6. **Push current branch**

## Constraints

> [!warning]
> - Never stage unrelated files
> - Never use `git add .` or `git add -A`
> - Run required checks before committing if code changed
> - Do not open PR unless explicitly asked
> - If not GitHub issue/PR work, do not post GitHub comment
> - If final comment already posted in session, do not post another
