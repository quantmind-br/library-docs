# Managing Your Installation

Manage, update, and configure DankMaterialShell after installation. The `dms` CLI works transparently whether DMS was started via systemd or manually.

## Service Management

### Systemd (Recommended)

Systemd provides automatic startup, proper session integration, and logging via journalctl.

**Enable and start:**

```bash
systemctl --user enable --now dms
```

**Common operations:**

```bash
systemctl --user status dms   # Check status
journalctl --user -u dms -f   # View logs
systemctl --user restart dms  # Restart (or: dms restart)
systemctl --user stop dms     # Stop
systemctl --user disable dms  # Disable autostart
```

> [!tip]
> If you installed via [[034-docs-1.2-dankinstall|dankinstall]], DMS is already configured as a systemd service. The installer runs `systemctl --user enable --now dms` during setup.

> [!warning]
> If using systemd, remove any `dms run` / `spawn "dms" "run"` lines from your compositor config to avoid running DMS twice.

#### niri: Per-Session Control

niri has native systemd session integration:

```bash
systemctl --user add-wants niri.service dms
```

DMS starts only under niri, not other desktop environments.

#### Other Compositors

Hyprland, Sway, and MangoWC lack systemd session targets. If you use multiple desktop environments and only want DMS on one:

```bash
systemctl --user disable dms
```

Then add `dms run` to your compositor's autostart (see Manual Launch below).

### Manual Launch

**Compositor autostart:**

```bash
# Hyprland (~/.config/hypr/hyprland.conf)
exec-once = dms run
# Sway (~/.config/sway/config)
exec dms run
# niri (~/.config/niri/config.kdl)
spawn-at-startup "dms" "run"
```

**Manual control:**

```bash
dms run      # Launch foreground
dms run -d   # Launch background/daemon
dms restart  # Restart
dms kill     # Kill
```

### Switching Between Methods

**From manual to systemd:**
1. Remove `dms run` from your compositor config
2. `systemctl --user enable --now dms`
3. Restart compositor or log out/in

**From systemd to manual:**
1. `systemctl --user disable --now dms`
2. Add `dms run` to compositor autostart
3. Restart compositor or log out/in

## Environment Variables

DMS and its themed applications need certain environment variables set.

> [!tip]
> dankinstall creates `~/.config/environment.d/90-dms.conf` with the necessary variables, loaded by systemd for all user sessions.

### Checking Your Environment

```bash
env | grep -E "QT_|GTK|XDG"           # See what's currently set
cat ~/.config/environment.d/90-dms.conf  # Check dankinstall's file (if it exists)
```

### Manual Configuration

If you did not use dankinstall, set variables in your compositor config:

**niri** (`~/.config/niri/config.kdl`):

```kdl
environment {
  QT_QPA_PLATFORM "wayland"
  QT_QPA_PLATFORMTHEME "gtk3"
  ELECTRON_OZONE_PLATFORM_HINT "auto"
}
```

**Hyprland** (`~/.config/hypr/hyprland.conf`):

```conf
env = QT_QPA_PLATFORM,wayland
env = QT_QPA_PLATFORMTHEME,gtk3
env = ELECTRON_OZONE_PLATFORM_HINT,auto
```

Or create `~/.config/environment.d/90-dms.conf`:

```ini
QT_QPA_PLATFORM=wayland
QT_QPA_PLATFORMTHEME=gtk3
ELECTRON_OZONE_PLATFORM_HINT=auto
```

> [!note]
> Changes to `environment.d` require logging out and back in (or rebooting).

## Updating

### Package Installations

| Distribution | Command |
|-------------|---------|
| Arch | `paru -Syu dms-shell-bin` or `dms-shell-git` |
| Fedora | `sudo dnf install dms` (COPR update via `dnf copr remove`) |
| Debian/Ubuntu | `sudo apt update && sudo apt upgrade dms` |
| OpenSUSE | `sudo zypper refresh && sudo zypper update dms` |
| NixOS | Update flake inputs, then `sudo nixos-rebuild switch` |

After package updates, restart the shell: `dms restart`.

### Manual Installations / Source Builds

For manually compiled dependencies (quickshell, niri, etc.), use the interactive TUI:

```bash
dms
# Navigate to Update → select packages to rebuild
```

## After Updating

1. Restart DMS: `dms restart`
2. Check [release notes](https://github.com/AvengeMedia/DankMaterialShell/releases) for breaking changes
3. Review Settings if new options are available
4. Update plugins if needed

## Uninstalling

### Package Installations

| Distribution | Stable | Git |
|-------------|--------|-----|
| Arch | `sudo pacman -Rns dms-shell-bin` | `dms-shell-git` |
| Fedora | `sudo dnf remove dms` | `dms-git` |
| Debian/Ubuntu | `sudo apt remove dms` | `dms-git` |
| OpenSUSE | `sudo zypper remove dms` | `dms-git` |

### Manual/Source Installs

```bash
systemctl --user disable --now dms
rm -rf ~/.config/quickshell/dms
sudo rm /usr/local/bin/dms
```

## Troubleshooting

**DMS won't start:**
- Check logs: `journalctl --user -u dms -n 50` (systemd) or run `dms run` in a terminal
- Verify quickshell is installed: `which qs`
- Kill stuck processes: `dms kill`

**Settings not applying:**
- Backup and remove `~/.config/DankMaterialShell/settings.json`
- Restart DMS to regenerate defaults

**Environment variables not working:**
- For `environment.d` changes: log out and back in
- For compositor config changes: restart the compositor
- Verify with `echo $QT_QPA_PLATFORMTHEME`

**Multiple instances running:**
