Tab Configs define reusable tab setups (directory, startup commands, pane layout, shell, theme) in TOML files stored in `~/.warp/tab_configs/`. Select a Tab Config from the `+` menu to open a fully configured tab.

## Creating a Tab Config

### From the UI

1. Click **+** in the tab bar → **+ New tab config**.
2. Warp creates a `.toml` file and opens it for editing.

### Manually

1. Create a `.toml` file in `~/.warp/tab_configs/` (snake_case name, e.g. `dev_server.toml`).
2. Define the layout using the schema below and save.

### Save an existing tab

Right-click any tab in the [[128-terminal-windows-vertical-tabs|vertical tabs]] panel or horizontal tab bar → **Save as new config**. Warp generates a `.toml` from the tab's layout, commands, and directory.

## Managing Tab Configs

Hover a Tab Config in the `+` menu to see a sidecar with options:

- **Edit config** — open the `.toml` file directly or use the footer to invoke the **Update tab config** skill (describe changes in natural language).
- **Remove** — remove from the `+` menu.
- **Make default** — set as the default `Cmd T` action for new tabs.

## Skills for Tab Configs

Warp includes built-in skills accessible via `/skills` in Agent Mode or from the editor footer:

- **Create Tab Config** — generate from a description (e.g., "create a 2x2 grid with one pane running my dev server").
- **Update Tab Config** — modify an existing Tab Config by description.

## TOML Schema

### Top-level fields

| Field | Type | Default | Description |
|---|---|---|---|
| `name` | string | — | Display name in `+` menu (required) |
| `title` | string | — | Custom tab title; supports `{{param}}` template variables |
| `color` | string | — | Tab color: `"black"`, `"red"`, `"green"`, `"yellow"`, `"blue"`, `"magenta"`, `"cyan"`, `"white"`. Values derive from your [[themes|Warp Theme]]. |

### Pane list

All panes are defined in a flat `[[panes]]` array. The first entry is the root of the pane tree.

#### Leaf node fields

| Field | Type | Default | Description |
|---|---|---|---|
| `id` | string | — | Unique identifier (required) |
| `type` | string | — | `"terminal"` (standard shell), `"agent"` (Agent Mode), `"cloud"` (cloud mode, no local shell) |
| `directory` | string | — | Initial working directory; supports `~` and `{{param}}` |
| `commands` | array of strings | — | Commands to run sequentially on open |
| `shell` | string | — | Shell executable (`"pwsh"`, `"zsh"`, `"bash"`, `"fish"`). Falls back to user default. |
| `is_focused` | bool | `false` | Gives initial focus if `true` (at most one pane) |

#### Split node fields

| Field | Type | Default | Description |
|---|---|---|---|
| `id` | string | — | Unique identifier (required) |
| `split` | string | — | `"horizontal"` (left-to-right) or `"vertical"` (top-to-bottom) |
| `children` | array of strings | — | Ordered list of child pane `id` values (min 2) |

> [!info]
> All children within a split are equally sized. No flex or proportion values.

### Parameters

Parameters prompt the user at open time. Declare with `[params.<name>]` and reference as `{{name}}`.

| Field | Type | Default | Description |
|---|---|---|---|
| `type` | string | `"text"` | `"text"` (freeform), `"branch"` (Git branch picker), `"repo"` (repository picker) |
| `description` | string | — | Label in the fill-in UI |
| `default` | string | — | Default value |

`{{autogenerated_branch_name}}` is reserved — Warp generates a unique worktree branch name instead of prompting.

## Examples

### Single pane

Opens a terminal in a project directory and starts a dev server:

```toml
name = "Dev Server"
[[panes]]
id = "server"
type = "terminal"
directory = "~/projects/my-app"
commands = ["npm run dev"]
```

### Two panes side by side

Editor and server in parallel, editor focused:

```toml
name = "Editor + Server"
[[panes]]
id = "split"
split = "horizontal"
children = ["editor", "server"]

[[panes]]
id = "editor"
type = "terminal"
directory = "~/projects/my-app"
is_focused = true

[[panes]]
id = "server"
type = "terminal"
directory = "~/projects/my-app"
commands = ["npm run dev"]
```

### Cross-shell development

Two panes with different shells:

```toml
name = "Cross-Shell"
[[panes]]
id = "split"
split = "horizontal"
children = ["bash-pane", "zsh-pane"]

[[panes]]
id = "bash-pane"
type = "terminal"
shell = "bash"

[[panes]]
id = "zsh-pane"
type = "terminal"
shell = "zsh"
```

### Worktree with parameters

Parameterized config that creates a new Git worktree on open:

```toml
name = "New Worktree"
title = "{{autogenerated_branch_name}}"

[params.branch]
type = "branch"
description = "Branch to worktree"

[[panes]]
id = "root"
split = "vertical"
children = ["main", "worktree"]

[[panes]]
id = "main"
type = "terminal"
directory = "~/projects/main-repo"

[[panes]]
id = "worktree"
type = "terminal"
directory = "~/projects/main-repo"
commands = ["git worktree add ../{{autogenerated_branch_name}} {{branch}}"]
```

> [!info]
> Create a worktree-based Tab Config directly from the `+` menu via **New worktree config**, selecting the source repo.
