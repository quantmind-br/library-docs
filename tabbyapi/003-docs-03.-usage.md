# 03. Usage

TabbyAPI is an API server for running ExllamaV2 models, supporting OpenAI and KoboldAI clients with expanded generation and administrative endpoints.

## API Server

TabbyAPI supports [OpenAI](https://platform.openai.com/docs/api-reference) and [KoboldAI](https://lite.koboldai.net/koboldcpp_api) clients, plus expanded generation parameters and administrative endpoints for loading, unloading, LoRAs, sampling overrides, and more.

> [!note]
> Developers adding full TabbyAPI support should use the [autogenerated documentation](https://theroyallab.github.io/tabbyAPI).

Example CURL request using the OpenAI completions endpoint:

```bash
curl http://localhost:5000/v1/completions \
-H "Content-Type: application/json" \
-d '{
  "model": "Meta-Llama-3-8B-exl2",
  "prompt": "Once upon a time,",
  "max_tokens": 400,
  "stream": false,
  "min_p": 0.05,
  "repetition_penalty": 1.05
}'
```

## Authentication

Every endpoint call requires authentication. Keys have two permission types:

- **API** — accesses non-invasive endpoints (generation, model list fetching).
- **Admin** — accesses protected resource endpoints (loading, unloading).

On list endpoints, API keys return only the currently loaded object; admin keys list the entire directory. For example, `/v1/models` returns the user-configured models directory only with an admin key.

Keep the admin key private; share only the API key with users.

If keys are compromised, shut down the server, delete `api_tokens.yml`, and restart — new keys are generated automatically.

To bypass authentication, set `disable_auth` to `True` in `config.yml`. This opens your instance to the world unless a third-party solution is used.

## Model Loading

> [!warning]
> All loading methods require an admin key.

Loading endpoints:

- `/v1/model/load` — loads a model from `model_dir` with provided parameters. If the model name differs from the currently loaded one, the existing model is unloaded first.
- `/v1/model/unload` — unloads all model tensors and terminates pending generation requests. Use only in emergencies or to free VRAM while keeping the server running.

Load requests are ephemeral — `config.yml` options don't apply. To use config options as fallback defaults, add them to the `use_as_default` key under model options.

Example CURL request for model loading:

```bash
curl http://localhost:5000/v1/model/load \
-H "Content-Type: application/json" \
-d '{
  "model_name": "Meta-Llama-3-8B-exl2",
  "max_seq_len": 8192,
  "tensor_parallel": true,
  "gpu_split_auto": false,
  "gpu_split": [20, 25],
  "cache_mode": "Q8"
}'
```

Load requests can include draft model parameters:

```bash
curl http://localhost:5000/v1/model/load \
-H "Content-Type: application/json" \
-d '{
  "model_name": "Meta-Llama-3-8B-exl2",
  ... Other parameters
  "draft_model": {
	draft_model_name: "TinyLlama-1B-32k-exl2",
	draft_rope_scale: 1.0
  }
}'
```

See the [autogenerated documentation](https://theroyallab.github.io/tabbyAPI/#operation/load_model_v1_model_load_post) for all available parameters.

## Inline Loading

> [!note]
> For fine-grained customization, use traditional endpoints instead. Inline loading doesn't accept per-request parameters.

Inline loading hooks into the model-switching logic used by frontends like OpenWebUI. Since model requests are ephemeral, `tabby_config.yml` provides per-model defaults.

1. Set `inline_model_loading` to `true` under the model block in `config.yml`.
2. Navigate to your model folder (e.g., `Meta-Llama-3-8B-exl2`) and create `tabby_config.yml`.
3. Place any `/v1/model/load` parameter in the file:

```yml
model:
  max_seq_len: 8192
  cache_mode: Q6
```

Add draft model options under `draft_model`:

```yml
model:
  max_seq_len: 8192
  cache_mode: Q6
draft_model:
	draft_model_name: TinyLlama-1B-32k-exl2
	draft_rope_scale: 1.0
```

Switch models by sending a request to `/v1/completions` or `/v1/chat/completions` with the `model` parameter set to the desired folder:

```bash
curl http://localhost:5000/v1/completions \
-H "Content-Type: application/json" \
-d '{
  "model": "Meta-Llama-3-8B-exl2"
  ... Other parameters
}'
```

This unloads the existing model and loads the new one with defaults from `tabby_config.yml`.
