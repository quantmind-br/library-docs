# 01. Getting Started

This guide covers installing, configuring, updating, and managing TabbyAPI, including model downloading and environment setup.

## Prerequisites

Install these before starting:

- [Python 3.x](https://www.python.org/downloads/release/python-31210/) (preferably 3.12) with pip
  - Do NOT install Python from the Microsoft Store — it causes pip issues.
  - Alternatively, use uv (preferred) or miniconda if present.

> [!note]
> Prefer a video guide? Watch the step-by-step tutorial on [YouTube](https://www.youtube.com/watch?v=03jYz0ijbUU)

> [!warning]
> CUDA and ROCm aren't prerequisites — torch installs them automatically. If installation fails (e.g., DLL load failed), install the toolkit manually:
>
> - [CUDA 12.x](https://developer.nvidia.com/cuda-downloads)
> - [ROCm 6.1](https://rocm.docs.amd.com/projects/install-on-linux/en/docs-6.1.0/how-to/prerequisites.html)

> [!warning]
> On Windows, "VS build tools needs to be installed" means a dependency wheel isn't available for your Python version. Install [VS build tools 17.8](https://aka.ms/vs/17/release.ltsc.17.8/vs_buildtools.exe) to build the wheel locally, then open an issue about the missing wheel.

## Installing

### For Beginners

1. Clone the repository: `git clone https://github.com/theroyallab/tabbyAPI`
2. Navigate to the directory: `cd tabbyAPI`
3. Run the start script (`start.bat` on Windows, `start.sh` on Linux):
   - Follow on-screen instructions and select the correct GPU library.
   - A virtual environment is created and dependencies installed automatically (if prerequisites are met).
4. The API starts with no model loaded. See [Download a Model](#download-a-model) below.

### For Advanced Users

1. Follow steps 1–2 in [For Beginners](#for-beginners).
2. Create a Python venv:
   - `python -m venv venv`
   - Activate it:
     - Windows: `.\venv\Scripts\activate`
     - Linux: `source venv/bin/activate`
3. Install pyproject features for your GPU:
   - CUDA 12.x: `pip install -U .[cu12]`
   - ROCm 5.6: `pip install -U .[amd]`
4. Start the API:
   - Run `start.bat/sh` — detects conda environments and skips venv checks.
   - Or run `python main.py` — won't auto-upgrade dependencies.

## Download a Model

TabbyAPI includes a built-in Hugging Face downloader accessible via API and terminal. Download a repository with a specific revision:

```bash
.\Start.bat download <repo name> --revision <branch>
```

Example with Turboderp's Llama 3.1 8B quants:

```bash
.\Start.bat download turboderp/Qwen2.5-VL-7B-Instruct-exl2 --revision 4.0bpw
```

For gated models, provide a HuggingFace access token (most exl2 quants aren't private):

```bash
.\Start.bat download meta-llama/Llama-3.1-8B --token <token>
```

Running `main.py` directly also triggers the downloader. For additional options, run `.\Start.bat download --help`.

## Configuration

A `config.yml` file tunes initial launch parameters and other settings.

**If you're okay with defaults, you don't need a config file.**

To create one, copy `config_sample.yml` to `config.yml`. All fields are commented — read descriptions and remove/comment out fields you don't need.

> [!warning]
> Because frontends don't send sampler settings per request, `config_sample.yml` includes a safe-defaults sampler override. If testing metrics or experimenting, remove `safe_defaults` from the `override_preset` key.

To manually set API keys, copy `api_keys_sample.yml` to `api_keys.yml` and fill in fields. This is less secure — autogenerated keys are preferred.

See also [[006-docs-02.-server-options|Server Options]] for full configuration parameters.

## Updating

### Update Scripts

Run scripts from the `update_scripts` folder:

- `update_deps` — updates dependencies to latest versions.
- `update_deps_and_pull` — updates dependencies and pulls the latest GitHub commit.

Scripts exit after running. Start TabbyAPI with `start.bat` or `start.sh`.

### Manual Update

Install pyproject features and update dependencies for your GPU:

- `pip install -U .[cu12]` — CUDA 12.x
- `pip install -U .[amd]` — ROCm 6.0

To skip updating wheel-based dependencies (torch, exllamav2, flash attention 2), use `pip install .` or pass `--nowheel` to start scripts.

### Update Exllamav2

> [!warning]
> These instructions are for advanced users.

> [!note]
> When installing a custom Exllamav2 wheel, always use `pip install .` during updates — otherwise each update overwrites your custom version.

- TabbyAPI enforces the latest Exllamav2 for compatibility.
- Upgrading via pyproject GPU features overwrites your installed wheel.
  - Fix: change the feature in `pyproject.toml` locally, open an issue/PR, or reinstall your exllamav2 version after upgrades.

Installation methods:

1. From a [wheel/release](https://github.com/turboderp/exllamav2#method-2-install-from-release-with-prebuilt-extension) (recommended) — match your CUDA and Python version (e.g., `cu121` + `cp311` = CUDA 12.1 + Python 3.11).
2. From [pip](https://github.com/turboderp/exllamav2#method-3-install-from-pypi): `pip install exllamav2` — JIT-compiled; first launch takes longer and may fail if the environment is misconfigured.
3. From [source](https://github.com/turboderp/exllamav2#method-1-install-from-source).

## Other Installation Methods

> [!warning]
> Methods other than venv may not work with startup scripts. These are for advanced users.

### Uv

> [!note]
> Uv is the preferred Python manager — recommended over conda and derivatives.

1. Install [Uv](https://docs.astral.sh/uv/getting-started/installation/#installation-methods) from Astral's website.
2. Continue from:
   - [For Beginners](#for-beginners) — Step 3. Start scripts detect uv and run appropriate commands.
   - [For Advanced Users](#for-advanced-users) — Step 3.

### Conda

1. Install [Miniconda3](https://docs.conda.io/projects/miniconda/en/latest/miniconda-other-installer-links.html) with Python 3.11 as base.
2. Create environment: `conda create -n tabbyAPI python=3.11`
3. Activate: `conda activate tabbyAPI`
4. Install optional dependencies if missing:
   - CUDA 12: `conda install -c "nvidia/label/cuda-12.4.1" cuda`
   - Git: `conda install -k git`
5. Clone TabbyAPI: `git clone https://github.com/theroyallab/tabbyAPI`
6. Continue from:
   - [For Beginners](#for-beginners) — Step 3. Start scripts detect conda and skip venv checks.
   - [For Advanced Users](#for-advanced-users) — Step 3.

### Docker

> [!note]
> If using custom dependency versions (e.g., dev ExllamaV2), build the Docker image yourself.

1. Install Docker and docker compose from the [docs](https://docs.docker.com/compose/install/).
2. Install the Nvidia container compatibility layer:
   - Linux: [Nvidia container toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html)
   - Windows: [Cuda Toolkit on WSL](https://docs.nvidia.com/cuda/wsl-user-guide/index.html)
3. Clone TabbyAPI: `git clone https://github.com/theroyallab/tabbyAPI`
4. Enter the directory: `cd tabbyAPI`
   - Optional: set up `config.yml` or `api_tokens.yml` ([configuration](#configuration)).
5. Update volume mounts in `docker/docker-compose.yml`:
```yml
volumes:
  # - /path/to/models:/app/models               # Change me
  # - /path/to/config.yml:/app/config.yml        # Change me
  # - /path/to/api_tokens.yml:/app/api_tokens.yml # Change me
```
6. Optional: build from source by editing `docker/docker-compose.yml`:
```yml
  # Uncomment this to build a docker image from source
  #build:
  #  context: ..
  #  dockerfile: ./docker/Dockerfile

  # Comment this to build a docker image from source
  image: ghcr.io/theroyallab/tabbyapi:latest
```
7. Run `docker compose -f docker/docker-compose.yml up` to build and start the server.
