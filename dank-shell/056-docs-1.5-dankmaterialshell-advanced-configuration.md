DankMaterialShell supports several advanced configuration options through environment variables prefixed with `DMS_`.

## Core Configuration

### DMS_RUN_GREETER

Enables greeter/login screen mode instead of regular shell mode. Used for display manager integration with greetd.

```bash
DMS_RUN_GREETER=1 dms run
```

### DMS_GREET_CFG_DIR

Specifies custom configuration directory for greeter mode (defaults to `/etc/greetd/.dms`). Useful for isolating greeter settings from user settings.

```bash
DMS_GREET_CFG_DIR=/custom/path dms run
```

### DMS_SOCKET

Custom Unix socket path for DMS internal services communication. Used by DMSService, NetworkService, SessionService, and PortalService for IPC.

```bash
DMS_SOCKET=/tmp/custom-dms.sock dms run
```

## Display & Rendering

| Variable | Default | Description |
|---|---|---|
| `DMS_DISABLE_MATUGEN` | `0` | Set to `1` or `true` to disable matugen dynamic theming system |
| `DMS_DISABLE_CAVA` | `0` | Set to `1` to disable the built-in Cava audio visualizer |
| `DMS_DISABLE_LAYER` | `0` | Set to `true` to disable layer effects on popout widgets |
| `DMS_DANKBAR_LAYER` | `top` | Wayland layer for DankBar panel: `bottom`, `overlay`, `background`, `top` |
| `DMS_POPOUT_LAYER` | `top` | Wayland layer for DankBar popout widgets: `bottom`, `overlay`, `background`, `top` |
| `DMS_MODAL_LAYER` | `top` | Wayland layer for modal windows (launcher, settings panel, popups): `bottom`, `overlay`, `background`, `top` |
| `DMS_OSD_LAYER` | `overlay` | Wayland layer for on-screen displays (volume, brightness): `bottom`, `overlay`, `background`, `top` |
| `DMS_NOTIFICATION_LAYER` | `top` | Wayland layer for notification popups: `bottom`, `overlay`, `background`, `top` |

### Shadow & Elevation Migration Notes (Power Users)

If you manually edit `settings.json`, use:

```text
~/.config/DankMaterialShell/settings.json
```

Important keys and compatibility notes:

- Global shadow direction (`m3ElevationLightDirection`) supports: `autoBar`, `top`, `topLeft`, `topRight`, `bottom`.
- Older/manual `left` or `right` values now fall back to `top`.
- Per-bar override still uses `barConfigs[].shadowIntensity` (and related color/opacity keys) to activate bar-specific shadows.
- Per-bar direction override keys:

  - `barConfigs[].shadowDirectionMode`: `inherit` | `autoBar` | `manual`
  - `barConfigs[].shadowDirection`: `top` | `topLeft` | `topRight` | `bottom`
- Older/manual per-bar `shadowDirection: left/right` now falls back to `top`.

Avoiding duplicate or unexpected shadow behavior:

- `barElevationEnabled: false` does not disable an active per-bar override by itself.
- If a bar still shows shadow, set that bar's `shadowIntensity` to `0`.
- `m3ElevationEnabled: false` disables global elevation, but an active per-bar override can still render for that bar.

Migration behavior:

- Legacy bar shadow state is migrated to `barElevationEnabled` for older configs.
- If `settings.json` is read-only, migration/write-back may not persist until the file is writable.

## System Integration

| Variable | Description |
|---|---|
| `DMS_DISABLE_POLKIT` | Set to `1` to disable native polkit integration |
| `DMS_PREFERRED_BATTERY` | UPower device path for dual-battery laptops (e.g., `/org/freedesktop/UPower/devices/battery_BAT0`) |
| `DMS_HIDE_TRAYIDS` | Comma-separated list of system tray icon IDs to hide |
| `DMS_DWL_TAG_COUNT` | Tag count for dwl (e.g., `5`) |

## Printing Configuration

| Variable | Default | Description |
|---|---|---|
| `DMS_IPP_HOST` | `localhost` | Hostname or IP of IPP/CUPS print server |
| `DMS_IPP_PORT` | `631` | Port number for IPP/CUPS print server |
| `DMS_IPP_USERNAME` | (none) | Username for IPP/CUPS authentication |
| `DMS_IPP_PASSWORD` | (none) | Password for IPP/CUPS authentication |

## Setting Environment Variables

> [!tip] Systemd / DankInstall Users
> If you manage DMS with systemd (including dankinstall users), set environment variables in `~/.config/environment.d/90-dms.conf`:
> ```ini
> TERMINAL=ghostty
> DMS_DISABLE_MATUGEN=1
> DMS_DANKBAR_LAYER=overlay
> DMS_HIDE_TRAYIDS=discord,spotify
> ```
> At least the TERMINAL variable should be present for the System Updates widget. Log out and back in for changes to take effect.
>
> Alternatively, run `systemctl --user edit dms` and add `Environment=` lines under `[Service]`. This only affects DMS and apps it launches, whereas `90-dms.conf` applies to all user sessions.

### niri

```kdl
environment {
  DMS_DISABLE_MATUGEN "1"
  DMS_DANKBAR_LAYER "overlay"
  DMS_HIDE_TRAYIDS "discord,spotify"
}
```

### Hyprland

```conf
env = DMS_DISABLE_MATUGEN,1
env = DMS_DANKBAR_LAYER,overlay
env = DMS_HIDE_TRAYIDS,discord,spotify
```

### Sway

```conf
set $DMS_DISABLE_MATUGEN 1
set $DMS_DANKBAR_LAYER overlay
set $DMS_HIDE_TRAYIDS discord,spotify
```

### Manual Launch

```bash
export DMS_DISABLE_MATUGEN=1
export DMS_DANKBAR_LAYER=overlay
dms run
```

## Use Cases

- **Disable dynamic theming** — `DMS_DISABLE_MATUGEN=1` — useful for performance testing or static themes only
- **Hide system tray icons** — `DMS_HIDE_TRAYIDS=discord,slack,teams` — clean up system tray
- **Fix bar layering issues** — `DMS_DANKBAR_LAYER=overlay` — if DankBar appears behind windows
- **Dual battery laptops** — `DMS_PREFERRED_BATTERY=/org/freedesktop/UPower/devices/battery_BAT0` — force specific battery
- **Performance tuning** — `DMS_DISABLE_LAYER=true` — disable layer effects on lower-end hardware
- **Remote print server** — set `DMS_IPP_HOST`, `DMS_IPP_PORT`, `DMS_IPP_USERNAME`, `DMS_IPP_PASSWORD`
