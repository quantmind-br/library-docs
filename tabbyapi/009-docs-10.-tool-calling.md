# Tool Calling in TabbyAPI

Tool calling is available for supported models, enabled by selecting a `tool_format` in the model config (also specifiable per-model via `tabby_config.yml`).

Most tool-calling models are also reasoning models — enable reasoning with appropriate tags (these cannot currently be inferred from the model's template).

```yml
model:
    reasoning: true
    reasoning_start_token: ""
    reasoning_end_token: ""
    tool_format: qwen3_5
```

## Supported Formats

| tool_format | Aliases | Model types |
|---|---|---|
| qwen3_coder | qwen3_5, step3_5 | Qwen3-Coder, Qwen3-Next, Qwen3.5 |
| minimax_m2 | | Minimax-M2, Minimax-M2.1, Minimax-M2.5 |
| glm4_5 | glm4_6, glm4_7 | GLM4.5, GLM4.6, GLM4.7 |
| mistral_old ¹ | | Older Mistral-family models |
| mistral | | Codestral 2508+, Devstral-Small 2507+, Magistral-Medium 2506+, Magistral-Small 2506+, Ministral-3 2512+, Mistral-Medium-3.1 2508+, Mistral-Small-3.2 2506+ |
| gemma4 | | Gemma 4-it |

> [!warning]
> **¹** Older Mistral models have unreliable tool calling support. Even newer releases often lack official chat templates or omit tool formatting. Tokenization changes frequently between releases. YMMV.

## Clients

TabbyAPI supports any software using the OAI tool calling API. The standard is evolving — clients and models differ in implementation.

### OpenCode

- OpenCode forces categorical sampling by default (`top-P = 1.0`), overriding TabbyAPI's defaults. If you see occasional random gibberish, configure sampling in OpenCode:

  ```json
  "agent": {
    "build": {
      "top_p": 0.8
    },
    "plan": {
      "top_p": 0.8
    }
  }
  ```

- OpenCode doesn't enable reasoning by default. For models that require it (e.g., Gemma4), set `force_enable_thinking: true` in TabbyAPI.
